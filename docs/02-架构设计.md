# 架构设计 —— C++ 模拟 ROS 节点系统

> 与 [`01-需求文档.md`](01-需求文档.md) 的需求编号对应。本文是**设计草案**，实现过程中允许调整，
> 但调整后记得回来同步本文（这也是"文档与代码一致"的一部分）。

## 1. 设计目标

| 目标 | 落实方式 |
| --- | --- |
| 松耦合 | 发布者只认识 `RosCore` 和话题名，不认识任何订阅者；订阅者同理 |
| 异步 | `publish()` 只是把消息塞给核心并立即返回，不等待、不关心谁收到 |
| 可扩展 | 新增节点类型只需继承 `Node`；新增消息类型只需扩展 `Message` |
| 健壮 | 非法输入一律抛语义清晰的异常，`main` 层统一兜底，程序不崩溃 |
| 规范 | const 正确性、智能指针、RAII、单一职责、头文件与实现分离 |

## 2. 分层结构

```
┌─────────────────────────────────────────────────────┐
│ 应用层   main.cpp —— 场景演示 + 全局 try-catch        │
├─────────────────────────────────────────────────────┤
│ 节点层   Publisher / Subscriber （继承 Node）         │
├─────────────────────────────────────────────────────┤
│ 核心层   RosCore 单例（注册表 / 消息转发 / 统一关闭）  │
├─────────────────────────────────────────────────────┤
│ 基础层   Node(抽象) · Message · Exception · Logger     │
└─────────────────────────────────────────────────────┘
```

依赖方向**只向下**：节点层依赖核心层与基础层，核心层依赖基础层，基础层不依赖任何人
（`RosCore` 对 `Publisher / Subscriber` 只需前向声明 + 指针，避免循环 include）。

## 3. 类关系

```
                    ┌──────────────────────────────────────────┐
                    │ RosCore（单例 FR-14, FR-15）              │
                    │  publishers_ : map<话题, vector<Pub*>>    │
                    │  subscribers_: map<话题, vector<Sub*>>    │
                    │  nodes_      : vector<Node*>   (顺序关闭) │
                    └────▲────────────────────────────▲─────────┘
     registerPublisher() │                            │ registerSubscriber()
                         │                            │
        ┌────────────────┴──────────┐   ┌─────────────┴──────────────┐
        │ Publisher : Node          │   │ Subscriber : Node          │
        │  + topic()                │   │  + topic()                 │
        │  + publish(rawData)  FR-07│   │  + onMessage(msg)   FR-11  │
        └────────────────▲──────────┘   └─────────────▲──────────────┘
                         │ 继承                          │ 继承
                    ┌────┴───────────────────────────────┴────┐
                    │ Node（抽象 FR-01~03）                    │
                    │  # name_            + name()            │
                    │  + init() = 0       + shutdown() = 0    │
                    └─────────────────────────────────────────┘

  Message（内容 + 时间戳，均只读 FR-12/13）：Publisher 构造 → RosCore 转发 → Subscriber 消费
  横切关注点：Exception 体系（FR-22~25）、Logger 分级日志（B-04/B-06）
```

## 4. 各类职责与要点

### 4.1 `Node`（抽象基类）

- 构造函数接收 `name` 并**当场校验**（空 / 纯空白 → `NodeException`），保证不存在"名字合法的半成品对象"。
- `name()` 返回 `const std::string&`，只读（FR-01）。
- `init()` / `shutdown()` 纯虚（FR-02）；`virtual ~Node() = default` —— **基类析构必须是虚的**，
  否则通过基类指针删除派生对象是未定义行为，这是答辩常问点。
- 可放 `bool inited_` 状态位，构造 / 关闭顺序错乱时可以拦一下（可选）。

### 4.2 `Message`

- 构造时（`explicit Message(std::string content)`）校验空内容 → `MessageException`（FR-24）。
- 时间戳在**构造时生成一次**并保存，语义是"消息创建时刻"；每次读取重新生成是错的。
- 只提供 `content()` / `timestamp()` 的 const 接口，无 setter（FR-13 → 不可变对象，天然线程安全）。

### 4.3 `Publisher`

- `init()`：输出初始化日志 → `RosCore::instance().registerPublisher(*this)`（FR-05）。
- `publish(const std::string& rawData)`：模拟"接收传感器字符串" → 构造 `Message` → 输出发布日志
  → `RosCore::instance().publish(topic_, msg)`（FR-07）。方法应为 `const` 或至少不修改状态。

### 4.4 `Subscriber`

- `init()`：日志 + `registerSubscriber(*this)`（FR-09）。
- `onMessage(const Message&)`：输出包含内容与时间戳的接收日志（FR-11）。设为 `virtual`，
  便于 B-01 里按消息类型做不同处理。

### 4.5 `RosCore`（单例）

- `static RosCore& instance()`：Meyers 单例（函数内 `static` 局部变量），C++11 起初始化线程安全，
  无需手动 `new` / `delete`；拷贝构造与赋值 `= delete`（FR-14）。
- 两张映射表：`unordered_map<string, vector<Publisher*>>` / `unordered_map<string, vector<Subscriber*>>`（FR-15）。
- `registerPublisher` / `registerSubscriber`：按话题追加，同时把节点记进 `nodes_`；**重名节点 → `NodeException`**（FR-23）。
- `publish(topic, msg)`：查表 → 逐个 `sub->onMessage(msg)`（FR-17）。
  - 话题从未注册过 → `TopicException`（FR-25）；
  - 话题存在但暂时没人订阅 → 只打一条 `WARN` 日志，不算错误（这个区分写进文档，评审会加分）。
- `shutdownAll()`：按注册顺序（或逆序）遍历 `nodes_` 调 `shutdown()`，并清空映射表（FR-18）。

### 4.6 异常体系（FR-22~25, B-05）

```
std::runtime_error
   └── RosException            // 项目统一基类，便于一次性 catch
         ├── NodeException     // 空节点名、重复注册
         ├── TopicException    // 话题不存在
         └── MessageException  // 空消息
```

- 继承自 `std::runtime_error` 的好处：`catch (const std::exception& e)` 也能兜住，符合标准库习惯。
- `main` 里分层捕获：具体异常（打印模块与原因）→ `RosException` → `std::exception` → `...`。

### 4.7 `Logger`（建议抽出来，B-04/B-06 的地基）

- `enum class LogLevel { Info, Warn, Error }`，`log(level, module, msg)` 统一格式：
  `[2026-01-01 12:00:00][INFO][Publisher:pub_temp] ...`
- 一处 `std::cout`（+ 可选 `std::ofstream`）比散落各处的 `cout` 好维护得多；
  若时间紧，可先在每个类里直接 `cout`，最后统一重构到 `Logger`（正好演示一次 `refactor` commit）。

## 5. 接口草案（可直接作为头文件起点）

```cpp
// include/Node.h
#pragma once
#include <string>

class Node {
public:
    explicit Node(std::string name);        // 空/空白名 -> NodeException
    virtual ~Node() = default;

    const std::string& name() const noexcept { return name_; }

    virtual void init() = 0;                // 日志 + 向 RosCore 注册
    virtual void shutdown() = 0;            // 日志

protected:
    static void validateName(const std::string& name);

    std::string name_;
    bool inited_{false};
};
```

```cpp
// include/Message.h
#pragma once
#include <string>

class Message {
public:
    explicit Message(std::string content);   // 空内容 -> MessageException

    const std::string& content() const noexcept { return content_; }
    const std::string& timestamp() const noexcept { return timestamp_; }

    virtual ~Message() = default;            // 为 B-01 自定义消息留扩展点

private:
    static std::string now();                // localtime_s + std::put_time

    std::string content_;
    std::string timestamp_;
};
```

```cpp
// include/Publisher.h
#pragma once
#include "Node.h"
#include <string>

class Publisher : public Node {
public:
    Publisher(std::string name, std::string topic);   // 空话题 -> TopicException

    const std::string& topic() const noexcept { return topic_; }

    void init() override;
    void shutdown() override;

    void publish(const std::string& rawSensorData) const;   // 构造消息并转发

private:
    std::string topic_;
};
```

```cpp
// include/Subscriber.h
#pragma once
#include "Node.h"
#include <string>

class Message;

class Subscriber : public Node {
public:
    Subscriber(std::string name, std::string topic);

    const std::string& topic() const noexcept { return topic_; }

    void init() override;
    void shutdown() override;

    virtual void onMessage(const Message& msg);             // 打印内容 + 时间戳

private:
    std::string topic_;
};
```

```cpp
// include/RosCore.h
#pragma once
#include <string>
#include <unordered_map>
#include <vector>

class Node;
class Publisher;
class Subscriber;
class Message;

class RosCore {
public:
    static RosCore& instance();

    RosCore(const RosCore&) = delete;
    RosCore& operator=(const RosCore&) = delete;

    void registerPublisher(Publisher& pub);
    void registerSubscriber(Subscriber& sub);

    void publish(const std::string& topic, const Message& msg);
    void shutdownAll();

private:
    RosCore() = default;
    ~RosCore() = default;

    std::unordered_map<std::string, std::vector<Publisher*>>  publishers_;
    std::unordered_map<std::string, std::vector<Subscriber*>> subscribers_;
    std::vector<Node*> nodes_;
};
```

> `RosCore` 里用裸指针 = "不拥有节点"的语义声明（节点由 `main` 或 `nodes/` 持有）。
> 若要做 B-03 动态增删，改成 `std::weak_ptr` 或 `shared_ptr` 并在析构时登出，否则会野指针。

## 6. 关键设计决策

| 决策点 | 选择 | 理由 / 取舍 |
| --- | --- | --- |
| 单例写法 | Meyers 单例（函数内 `static`） | 线程安全初始化、无需手动释放；比"饿汉式 + 私有静态成员"更简洁 |
| 名称校验时机 | 构造函数内抛异常 | 对象一出生就合法，杜绝"半成品"；放在 `init()` 里校验会留下非法对象 |
| 消息传递 | `const Message&` | 零拷贝 + 只读语义；`shared_ptr` 只在跨线程/异步队列时才需要 |
| 注册表结构 | `unordered_map<string, vector<...>>` | 按话题 O(1) 查找 + 天然支持"一话题多订阅者"（FR-17） |
| 节点所有权 | 基础版裸指针，B-03 换 `weak_ptr` | 别为了加分提前上智能指针，先把主干跑通 |
| 日志 | 统一 `Logger` + 级别 | 为 B-04 落盘、B-06 分级铺路；比满屏 `cout` 好讲 |
| 时间戳 | 构造时生成、不可变 | 语义正确，且对象不可变后无并发问题 |
| 异常基类 | 继承 `std::runtime_error` | 与 `catch (std::exception&)` 生态兼容 |

## 7. 一个完整回合的时序（FR-19~21）

```
main:
  1. RosCore::instance()                          // 单例首次创建
  2. pub  = Publisher("pub_temp",  "/sensor/temp")
     sub1 = Subscriber("sub_mon",  "/sensor/temp")
     sub2 = Subscriber("sub_log",  "/sensor/temp")
  3. pub->init()   -> INFO 初始化日志 -> registerPublisher  ("/sensor/temp" -> [pub])
     sub1->init()  -> INFO 初始化日志 -> registerSubscriber ("/sensor/temp" -> [sub1])
     sub2->init()  -> 同上                                  ("/sensor/temp" -> [sub1, sub2])
  4. pub->publish("25.3C")                        // 连续多帧同理，不等任何人
       -> Message("25.3C") 生成时间戳
       -> INFO 发布日志
       -> RosCore::publish("/sensor/temp", msg)
            -> sub1->onMessage(msg)  INFO 接收日志（内容 + 时间戳）
            -> sub2->onMessage(msg)  同上
  5. RosCore::instance().shutdownAll()
       -> 遍历 nodes_ -> pub/sub 各自 shutdown() -> INFO 关闭日志 -> 清空映射表
```

## 8. 加分项插入点（先做主干，再按需挂接）

| 加分项 | 改动位置 | 说明 |
| --- | --- | --- |
| B-01 自定义消息 | `Message` 加 `virtual type()` / 基类化，派生 `TemperatureMessage{temp, humidity}` | `onMessage` 里按 `type()` 分支；`Message` 已预留虚析构 |
| B-02 服务/客户端 | 新增 `Service` / `Client` 类 + `RosCore` 里加服务表 | 同步调用：`client.call(req)` 直接 `return svc->handle(req)`，与话题的异步形成对照 |
| B-03 动态增删 | 注册表换 `weak_ptr`，新增 `unregisterNode(name)` | 记得处理"删除后仍在表里"的悬空问题 |
| B-04 日志落盘 | `Logger::setFile(path)`，同时写 `cout` 与 `ofstream` | 文件放 `logs/`（已在 `.gitignore`） |
| B-05 全局异常处理 | `main` 里集中 try-catch；`Logger` 输出 ERROR 到文件 | 可加 `std::set_terminate` 兜底演示 |
| B-06 日志分级 | `LogLevel` + 按级别着色/过滤 | 与 B-04 一起做最省事 |

## 9. 待定 / 需要你自己拍板的点

1. **节点名唯一性范围**：全局唯一（推荐，与 FR-23 一致）还是"同类型内唯一"？
2. **空话题名**是否也算非法（建议算，抛 `TopicException`）。
3. 发布到"注册过但当前无订阅者"的话题：只 `WARN` 不抛异常（推荐），还是按 FR-25 严格抛？
4. 是否需要多线程发布（加分展示点，但要加 `mutex`，风险与收益自己权衡）。

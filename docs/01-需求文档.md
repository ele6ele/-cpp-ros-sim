# 需求文档 —— C++ 模拟 ROS 节点系统

> 依据课程《C++ 大作业》要求整理。需求编号供后续设计、测试、commit 引用（例如 `feat: 实现 FR-04`）。

## 一、项目背景

ROS 是机器人领域主流的分布式通信框架，"节点 - 话题"松耦合通信模式是多模块协同工作的核心基础。
本次不要求掌握真实 ROS 的 API，而是用 C++ **模拟实现 ROS 最核心的通信逻辑**，本质是检验 C++ 编程水平。

## 二、术语表

| 术语 | 定义 |
| --- | --- |
| 节点 Node | 系统的最小功能单元，分为发布者节点和订阅者节点，每个节点有唯一名称 |
| 话题 Topic | 节点间通信的"通道"，发布者向话题发消息，订阅者从话题收消息 |
| 消息 Message | 通信的数据载体，包含业务内容和时间戳 |
| 发布者 Publisher | 向指定话题发布消息的节点 |
| 订阅者 Subscriber | 订阅指定话题并接收消息的节点 |
| 单例模式 | 保证 ROS 核心管理类全局仅有一个实例 |

## 三、功能需求

### 3.1 节点基类 Node

- **FR-01** 作为所有节点的抽象父类，封装唯一的节点名称，并提供**只读**的名称获取方法。
- **FR-02** 定义初始化接口与关闭接口（纯虚），要求子类实现，并输出对应的初始化 / 关闭日志。
- **FR-03** 为发布者、订阅者统一基础行为规范（公共状态与公共接口放在基类）。

### 3.2 发布者 Publisher

- **FR-04** 继承 `Node`，扩展**话题名称**属性并提供其只读接口。
- **FR-05** 初始化接口：输出初始化日志，并向 ROS 核心**注册自身**。
- **FR-06** 关闭接口：输出关闭日志。
- **FR-07** 核心发布功能：模拟接收传感器字符串信息 → 创建消息对象 → 输出发布日志 → 将消息转发至 ROS 核心对应话题。

### 3.3 订阅者 Subscriber

- **FR-08** 继承 `Node`，扩展**话题名称**属性并提供其只读接口。
- **FR-09** 初始化接口：输出初始化日志，并向 ROS 核心**注册自身**。
- **FR-10** 关闭接口：输出关闭日志。
- **FR-11** 核心订阅功能：接收消息对象，输出**包含消息内容和时间戳**的接收日志，完成消息的被动接收。

### 3.4 消息封装 Message

- **FR-12** 封装字符串类型的消息内容，并**自动生成**格式为 `YYYY-MM-DD HH:MM:SS` 的系统时间戳。
- **FR-13** 仅提供读取消息内容与时间戳的公有接口（数据封装 + 访问可控，不允许外部修改）。

### 3.5 ROS 核心管理模块（RosCore）

- **FR-14** 采用**单例模式**保证全局唯一实例。
- **FR-15** 维护"话题 - 发布者"和"话题 - 订阅者"两类映射关系。
- **FR-16** 提供发布者 / 订阅者的**注册方法**，用于更新映射表。
- **FR-17** 核心消息转发功能：将指定话题的 `Message` 对象推送给该话题下**所有**订阅者。
- **FR-18** 提供统一关闭方法：遍历所有节点，调用其关闭方法，完成全局节点关闭。

### 3.6 系统整体行为

- **FR-19** 支持多个发布者、多个订阅者节点的创建，以及其对应映射关系，并输出初始化日志。
- **FR-20** 发布者可**连续发布**消息，发布过程**无需等待**订阅者响应（异步通信语义）。
- **FR-21** 所有节点按流程完成"初始化 → 消息交互 → 关闭"的完整生命周期。

### 3.7 异常与健壮性（必做）

面对下列非法输入或操作时，**程序禁止崩溃**，须抛出语义清晰的异常信息：

- **FR-22** 空节点名（空字符串 / 纯空白）
- **FR-23** 重复节点注册（同名节点已存在）
- **FR-24** 空消息发布（内容为空）
- **FR-25** 向不存在的话题转发消息 / 订阅不存在的话题

> 建议：异常类型区分开（`NodeException` / `TopicException` / `MessageException`），
> 在 `main` 里统一 `try-catch` 捕获并打印，保证单个用例失败不影响后续流程。

## 四、加分功能（选做，按性价比排序）

- **B-01** 自定义消息类型：如包含温度、湿度、时间戳的传感器消息（可抽象 `Message` 基类 + 派生）。
- **B-02** 服务 / 客户端：同步"请求 - 响应"通信模式（与话题的异步模式形成对照）。
- **B-03** 运行时动态添加 / 删除节点。
- **B-04** 所有消息收发日志**持久化写入文本文件**。
- **B-05** 全局自定义异常处理机制：自定义异常类 + 全局异常捕获器（异常日志输出到控制台和文件）。
- **B-06** 日志分级：`INFO` / `WARN` / `ERROR`，分类输出。

## 五、非功能需求

- **NFR-01** 遵循严格 C++ 编码习惯（const 正确性、RAII、智能指针、避免裸 new/delete）。
- **NFR-02** 开发前编写需求文档与架构设计文档（本文件 + `02-架构设计.md`）。
- **NFR-03** 开发完成后编写技术文档与用户手册。
- **NFR-04** 进行测试：建议编写结构化测试用例，覆盖**正常场景、边界场景、异常场景**。

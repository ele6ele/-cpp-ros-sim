# 开发路线图 —— 从骨架到交作业

原则：**先跑通主干，再加分；每完成一小步就提交**。作业明确要求"禁止一次性提交所有代码"，
下面每个节点就是一次（或几次）commit，按顺序做即可，中途每一步程序都能编译运行。

建议节奏：4 天左右，每天 2 个里程碑。总代码量 600–900 行，别堆，写清楚更重要。

## M1 Node 抽象基类 + 异常体系骨架

- **文件**：`include/Exception.h`、`include/Node.h`、`src/Node.cpp`
- **要点**
  - `RosException : public std::runtime_error`，先派生 `NodeException`（后面 M5 再补 `TopicException` / `MessageException`）
  - `Node` 构造函数 `explicit Node(std::string name)`，内部调用 `validateName()`：`name.empty()` 或全是空白（`name.find_first_not_of(" \t\n\r") == npos`）→ 抛 `NodeException`
  - `name()` 返回 `const std::string&`；`init()` / `shutdown()` 纯虚；析构虚
  - 顺手在 `src/main.cpp` 里试一下：`Node` 是抽象类不能实例化（编译期就报错，这就是"抽象父类"的意义）
- **验收**：能编译；临时写个 `Publisher` 之后（M4）名字为空会抛异常。本步可先只验证编译
- **提交**：`feat(node): 新增 Node 抽象基类与节点名校验` + `feat(exception): 新增 RosException/NodeException 异常体系`

---

## M2 Message 消息封装与时间戳

- **文件**：`include/Message.h`、`src/Message.cpp`
- **要点**
  - 构造函数校验空内容 → `MessageException`（需要 `Exception.h` 里加上这个类，或先复用 `NodeException`，M5 再拆）
  - 时间戳：`std::time(nullptr)` → `localtime_s(&tmBuf, &t)` → `std::put_time(&tmBuf, "%Y-%m-%d %H:%M:%S")` 写入 `std::ostringstream`
  - 时间戳只在构造时生成一次；内容与时间戳都只读
- **验收**：`Message m("25.3C"); std::cout << m.content() << " " << m.timestamp();` 输出形如 `25.3C 2026-01-01 12:00:00`
- **提交**：`feat(message): 实现消息封装与 YYYY-MM-DD HH:MM:SS 时间戳`

---

## M3 RosCore 单例与注册表

- **文件**：`include/RosCore.h`、`src/RosCore.cpp`
- **要点**
  - `static RosCore& instance(){ static RosCore inst; return inst; }`（Meyers 单例），拷贝构造 / 赋值 `= delete`
  - 两张表 + `nodes_`；`registerPublisher` / `registerSubscriber` 按话题追加，重名节点 → `NodeException`
  - 先用最小验证：两个 `Subscriber` 注册到同一话题，打印 `subscribers_["/topic"].size() == 2`
- **验收**：单例地址不变（打印 `&RosCore::instance()` 两次结果相同）
- **提交**：`feat(core): 实现 RosCore 单例与主题订阅注册表`

## M4 Publisher / Subscriber + 消息转发（主干打通）

- **文件**：`include/Publisher.h`、`src/Publisher.cpp`、`include/Subscriber.h`、`src/Subscriber.cpp`、`src/RosCore.cpp`（补 `publish`）
- **要点**
  - `Publisher::init()`：初始化日志 → `registerPublisher(*this)`；`publish()`：构造 `Message` → 发布日志 → `RosCore::publish(topic_, msg)`
  - `Subscriber::init()`：日志 + 注册；`onMessage(const Message&)`：接收日志（**内容 + 时间戳都要打**）
  - `RosCore::publish`：查 `subscribers_[topic]`，遍历调用 `onMessage`；`shutdownAll()` 遍历 `nodes_` 调 `shutdown()`
- **验收**：1 个发布者 + 2 个订阅者，发一条消息两个订阅者都打印接收日志，输出顺序稳定
- **提交**（建议拆 3 次）
  - `feat(publisher): 实现发布者节点初始化与消息发布`
  - `feat(subscriber): 实现订阅者节点初始化与消息接收`
  - `feat(core): 实现话题消息转发与全局节点关闭`

> 这一步是全作业的核心，做完就可以截个图交差；后面都是健壮性和加分。

## M5 异常补全 + 日志分级

- **文件**：`include/Exception.h`、`include/Logger.h`、`src/Logger.cpp`、各模块改造
- **要点**
  - 补 `TopicException`（话题不存在 / 空话题）、`MessageException`（空消息）
  - 4 类非法输入全部覆盖：空节点名、重复注册、空消息、不存在话题（FR-22~25）
  - `Logger`：`enum class LogLevel{Info,Warn,Error}`，统一格式输出；把各处的 `cout` 换过去
  - `main` 里加分层 `try-catch`：具体异常 → `RosException` → `std::exception` → `...`
- **验收**：写 4 行"故意犯错"的代码，每行都打印出清晰的中文错误信息且**程序继续往下跑**
- **提交**：`feat(logger): 引入分级日志` / `fix(core): 补充话题不存在的异常处理` 等，一个场景一个 commit

## Git 提交规范

- 格式：`类型(范围): 简短说明`，类型用 `feat` / `fix` / `docs` / `test` / `refactor` / `chore`
- 一个 commit 只做一件事；提交前 `git status` 确认没把 `build/` 加进去
- 想让提交历史更好看，可以在 `feature/node` 这类分支上开发再合并：
  ```powershell
  git switch -c feature/node
  # ...写代码...
  git commit -m "feat(node): 实现 Node 基类与名称校验"
  git switch main
  git merge --no-ff feature/node -m "merge: Node 基类"
  ```
  （老师要"增量痕迹"，分支 + merge 的图形历史是最直观的证据）

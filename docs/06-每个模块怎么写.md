# 每个模块该怎么写（自己动手版）

> 这份文档不给你代码，只给"思考顺序 + 自查清单"。
> 用法：**每天只读一节**，照着里面的问题自己回答，然后动手。写完一节就来勾掉。
> 已有的 `Node`/`Exception` 是我写的**参考实现**，你可以照着结构和注释风格写自己的版本，不要照抄逻辑以外的部分（尤其是别把它的注释改个名字就交）。

## 通用四步法（每个模块都这么走）

1. **先想**：回答"这一节的问题清单"，把答案写在纸上或文档里（想不清就别写代码）
2. **先写 `.h`**：成员变量 + 函数声明，**不写函数体**
3. **再写 `.cpp`**：一个函数一个函数地实现，每写完一个就 `Ctrl+Shift+B` 编译一次
4. **验证 + 提交**：`run.bat` 看到预期输出 → `git commit`（提交信息参考每节末尾）

> 编译一次的成本只有几秒，养成"写 10 行就编译"的习惯，报错永远只有一两个，好查。

## 第 1 天 · Node（对照参考实现重写一遍）

**目标**：一个类，能存名字、能给外面看名字、定两个空接口让子类去填。

**先回答这 6 个问题**（答案就在参考实现里，自己找出来）

1. 名字用什么类型存？`std::string` 还是 `const char*`？为什么？
2. `name()` 返回 `std::string`（拷贝一份）还是 `const std::string&`（只给看）？外部拿到引用后能改吗？
3. 构造函数的参数为什么写 `std::string name`（传值）而不是 `const std::string&`？
4. 名字为空时，在**构造函数里**拦，还是在 `init()` 里拦？两者差别是什么？（提示：哪个能保证"对象一出生就合法"）
5. `init()` / `shutdown()` 为什么是**纯虚**（`= 0`）？如果写成普通虚函数给个空实现，会有什么风险？
6. 析构函数为什么必须加 `virtual`？（提示：`Node* p = new Publisher(...); delete p;` 会怎样）

**写的顺序**：`.h` 里写成员和声明 → `.cpp` 里写构造函数 → 写校验函数 → 编译 → 在 `main.cpp` 里造一个子类试一下。

**验证**：故意传 `""` 和 `"   "`，看是不是抛异常且程序不崩（`main.cpp` 里的 `checkIllegalName` 就是干这个的）。

**常见坑**：`class {...};` 结尾忘分号；`.cpp` 忘了 `#include "Node.h"`；把函数体写进 `.h` 导致 `LNK2005 重复定义`。

**提交**：`feat(node): 实现 Node 抽象基类与节点名校验`

## 第 2 天 · Message（消息 + 时间戳）

**目标**：一条消息 = 一段文字 + 写这条消息的时间，两者都只能读不能改。

**先回答**

1. 成员变量需要几个？分别存什么？
2. 时间戳存成 `std::string`（`"2026-01-01 12:00:00"`）还是 `time_t`（一串秒数）？如果要打印给人看，哪种省事？
3. 时间戳在**什么时候**生成？构造时一次，还是每次读取时现算？为什么后者是错的？
4. 内容为空要不要拦？标准定成"空串"还是"空串或全空白"？（建议和 Node 保持一致，理由是什么？）
5. 要不要提供 `setContent()` 之类的修改接口？（提示：不提供，对象就天然安全，谁也没法在转发途中改掉内容）

**唯一需要查资料的地方**：把"当前时间"变成 `"2026-01-01 12:00:00"`。

```
三步：time() 拿秒数 → localtime_s() 拆成年月日时分秒 → strftime() 排成字符串
```

坑：MSVC 里必须用 `localtime_s`（`localtime` 会报 C4996）；`tm` 变量要零初始化 `tm tmv{};`；缓冲区给 32 字节足够。

**验证**：造 3 条消息，中间 `Sleep(1000)` 一秒，看时间戳是不是递增/更新；再传 `""` 看是否抛 `MessageException`（此时要在 `Exception.h` 里加上这个类）。

**提交**：`feat(message): 实现消息封装与时间戳生成`

## 第 3 天 · RosCore（传达室）

**目标**：全局只有一个传达室，它记得"谁发哪个话题、谁听哪个话题"，并负责转发。

**先回答**

1. 怎么保证"全局只有一个"？构造函数设成 `private`，外面怎么拿到它？（查"单例模式"最简单的写法：函数里的 `static` 局部变量）
2. 有人不小心 `RosCore a = RosCore::instance();` 会怎样？怎么禁止？（拷构函数和赋值运算符 `= delete`）
3. 需要几张表？"话题 → 发布者" 和 "话题 → 订阅者" 能不能合成一张？为什么建议分两张？
4. 一张表里"一个话题"对应**一个**订阅者还是**一组**？用什么容器？（`unordered_map<string, vector<Subscriber*>>`，想想为什么是 `vector`）
5. 注册函数除了往表里塞，还要不要额外记一份"所有节点"的名单？为什么需要（提示：第 5 个问题就是"统一关闭"要遍历谁）
6. `publish(topic, msg)` 的内部动作分几步？（查表 → 判空 → 遍历 → 挨个调 `onMessage`）
7. `shutdownAll()` 关完以后要不要清空表？不清空会怎样（重复关闭/野指针）？

**验证**：`main` 里打印两次 `&RosCore::instance()`，两个地址必须一样；注册 2 个订阅者到同一话题后，看表里是不是有 2 个。

**常见坑**：忘了 `private` 构造导致能 new 多个；注册表里存了指针但节点是局部变量，函数返回后指针悬空（`main` 里节点要活到 `shutdownAll` 之后）。

**提交**：`feat(core): 实现 RosCore 单例与话题注册表`

## 第 4 天 · Publisher + Subscriber + 转发（主干打通）

**目标**：一个发、多个收。这是全作业的高潮，做完就能截图。

**先回答**

1. 两个类都要继承 `Node`，那"话题名"该放哪？（各自类里加 `topic_`，因为 Node 只管名字）
2. 构造函数要不要顺便校验话题非空？（建议要，抛 `TopicException`）
3. **注册放在构造函数里，还是放在 `init()` 里？** 作业要求是 `init()`，为什么这样更合理？（提示：构造函数执行时对象还"没构造完"，而且 `main` 里多半是先造完所有节点再统一 init）
4. `Publisher::publish()` 的参数类型？内部动作按顺序是哪几步？（造 `Message` → 打印发布日志 → 调 `RosCore::publish`）
5. `Message` 要不要作为 `Publisher` 的成员存起来？（不要。每条消息是独立的一条，用完就丢，存起来只会覆盖/泄漏）
6. `Subscriber::onMessage()` 要不要设成 `virtual`？（为第 7 天的加分项留口子）
7. `onMessage` 里能不能抛异常？（转发是循环调用，一个订阅者抛异常会中断其他人的接收——想想这在真实系统里意味着什么）

**验证顺序**（别一次写完）：
① 先让发布者 `init` 后能打印日志 → 编译
② 再让 `RosCore::publish` 能列出该话题的订阅者数量 → 编译
③ 最后接上 `onMessage` 打印 → 跑起来看 1 发 3 收

**提交**（拆 3 次）：`feat(publisher): ...` / `feat(subscriber): ...` / `feat(core): 实现话题消息转发与全局关闭`

## 第 5 天 · 把"出错"处理好 + 日志分级

**目标**：4 种故意写错的操作都不崩，且提示看得懂。

**先回答**

1. 4 个场景分别在**哪一层**拦截？（空名字→Node；重复注册→RosCore；空消息→Message；话题不存在→RosCore）
2. 重复注册怎么判断"重复"？按名字比还是按指针比？比名字要不要区分类型（发布者叫 `a`、订阅者也叫 `a` 算冲突吗）？
3. 话题"注册过但暂时没人订阅"要不要报错？（建议只打 `WARN`，不要抛异常——想想为什么）
4. `main` 里要不要给每段操作单独 try-catch？还是一次包住全部？（提示：包全部的话，第一个异常后面的演示都不执行了）
5. 日志想统一成什么格式？`[时间][级别][模块] 内容`？统一后改格式只需改一处，这是为什么值得单独写个 `Logger`。

**验证**：`main` 里故意写 4 行错误操作，每行都要打印中文提示，且**程序继续往下跑**。

**提交**：一个场景一个 `fix(...)`，例如 `fix(core): 话题不存在时抛出 TopicException`

## 第 6 天 · 演示场景 + 测试 + 文档

**目标**：一键运行就是完整的"初始化 → 收发 → 关闭"，并留下证据。

1. `main` 的场景：2 个发布者（`/temp`、`/hum`）+ 2 个订阅者 + 连发 3 条 + `shutdownAll`
2. 照着 [`03-开发路线图.md`](03-开发路线图.md) 的 T-01 ~ T-11 表逐条跑，填 [`05-测试报告.md`](05-测试报告.md)
3. 补 [`04-用户手册.md`](04-用户手册.md)：怎么编译、怎么运行、贴一段真实输出
4. 截图/录屏：这是最省力的"证明我做了"

**提交**：`test: 覆盖正常/边界/异常场景` / `docs: 完成用户手册与测试报告`

## 第 7 天起 · 加分项（挑 2 个就够）

按性价比：**日志落盘 + 分级**（半小时）→ **自定义消息**（1 小时）→ **服务/客户端**（2 小时）→ **动态增删**（2 小时，要改用 `weak_ptr`）。

每个加分项单独一个 commit，提交信息里写清做了什么。

## 卡住时的求助模板

发消息给我时按这四项说，我能直接定位：

1. 我在写哪个类、哪个函数（例如"`RosCore::publish`"）
2. 我期望它做什么（"把消息发给该话题所有订阅者"）
3. 实际发生了什么（"程序直接崩了 / 打印了 0 条"）
4. 报错原文（直接复制终端里的红字，不要只描述"报错了"）

> 只描述"报错了"我需要来回猜三轮；贴原文我一眼就能说"第 12 行少了 `&`"。
